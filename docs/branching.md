# 分岐設計

正本は `content/branching.ts`。この資料はその読み下しである。
数値と表は `tests/branching.test.ts` が独立に持っており、実装と資料の
どちらが動いたのかを機械的に検出できるようにしてある。

## 1. 全体構造

```
序章・第一章        一本道
  ↓
第二章  調査ハブ    4か所から2か所を選ぶ（6通り）
  ↓
第三章  同行者      3ルートから1つ選ぶ（3通り）
  ↓
第四章              合流（暗号解読・遺体発見）
  ↓
第五章  最終選択    5種（うち1つは条件付きの秘密選択）
  ↓
終幕                6エンディング
```

大きな選択は「別の情報を見る（調査）」「別の人物を信じる（同行者）」
「最後に判断する（最終選択）」の三段階に絞ってある。

## 2. 調査地点と手掛かり

| ID | 場所 | 手掛かり | 系統 |
|---|---|---|---|
| `desk` | 書斎の書き物机 | `ledger_name` | 系統1 過去 |
| | | `cipher_key` | 秘密の鍵 |
| `attic` | 屋根裏のハドスンの部屋 | `sailors_knot` | 系統2 今夜の道 |
| | | `hudson_kit` | 系統3 偽装 |
| `village` | 村の宿と郵便局 | `news_clip` | 系統1 過去 |
| | | `tide_table` | 系統3（`boat_log` と対） |
| `fen` | 沼と舟着き場 | `red_clay` | 系統2 今夜の道 |
| | | `boat_log` | 系統3（`tide_table` と対） |

各地点は必ず「異なる系統の手掛かり2つ」を出す。同じ系統の手掛かりを
一か所で二つ配ると、独立した二択に見えて実際には一つの選択になるためである。

## 3. 同行者ルート

| ID | 選択 | 手掛かり | 系統 |
|---|---|---|---|
| `victor` | ヴィクターに全部話す | `victor_testimony` | 系統3 偽装（フラグで直接成立） |
| `fordham` | フォーダム医師と組む | `fordham_note` | 系統1 過去 |
| | | `hired_gig` | 系統2 今夜の道 |
| `alone` | 一人で沼を見張る | `night_watch` | 系統3 偽装（フラグで直接成立） |

`fordham` は二系統を補うが、系統3（偽装）には寄与しない。
`victor` と `alone` は系統3を確実にするが、他は補わない。
この非対称が、同行者選択を「安全な一択」にしないための設計である。

## 4. 三つの補強証拠系統

共通ルートで、プレイヤーは既に次を知っている。

- 老トレヴァーの本名と前歴（手記）
- ハドスンが三十年前の唯一の生存者であること
- 書付が「逃げろ」という警告であること

任意の手掛かりは、それ単独で犯行を証明するものではない。
ビードウズが持ち出しうる三つの反論を、それぞれ封じるための補強である。

| 系統 | 封じる反論 | 成立条件 |
|---|---|---|
| 系統1 過去 | 「トレヴァー氏とは縁もゆかりもない文通相手だ」 | `ledger_name` ∨ `news_clip` ∨ `fordham_note` |
| 系統2 今夜の道 | 「わたしはハンプシャーから一歩も出ていない」 | `sailors_knot` ∨ `red_clay` ∨ `hired_gig` |
| 系統3 偽装 | 「ハドスンは自分の足で出ていった。事件など起きていない」 | `hudson_kit` ∨ (`tide_table` ∧ `boat_log`) ∨ `trustVictor` ∨ `alone` |

## 5. 18通りの全列挙

○＝成立、×＝不足。

| 調査 | 同行者 | 系統1 | 系統2 | 系統3 | 秘密選択 | ビードウズ告発 |

| desk + attic | victor | ○ | ○ | ○ | 可 | END 01 |
| desk + attic | fordham | ○ | ○ | ○ | 可 | END 01 |
| desk + attic | alone | ○ | ○ | ○ | 可 | END 01 |
| desk + village | victor | ○ | × | ○ | — | END 02 |
| desk + village | fordham | ○ | ○ | × | — | END 02 |
| desk + village | alone | ○ | × | ○ | — | END 02 |
| desk + fen | victor | ○ | ○ | ○ | 可 | END 01 |
| desk + fen | fordham | ○ | ○ | × | — | END 02 |
| desk + fen | alone | ○ | ○ | ○ | 可 | END 01 |

| attic + village | fordham | ○ | ○ | ○ | — | END 01 |
| attic + village | alone | ○ | ○ | ○ | — | END 01 |
| attic + fen | victor | × | ○ | ○ | — | END 02 |
| attic + fen | fordham | ○ | ○ | ○ | — | END 01 |
| attic + fen | alone | × | ○ | ○ | — | END 02 |
| village + fen | victor | ○ | ○ | ○ | — | END 01 |
| village + fen | fordham | ○ | ○ | ○ | — | END 01 |
| village + fen | alone | ○ | ○ | ○ | — | END 01 |

**集計：三系統が揃うのは12通り、いずれか不足が6通り。秘密選択が出るのは5通り。**

読み取れること。

- 良い結末は一本道ではない。4種類の調査組み合わせから到達できる。
- `desk + village` は三通りすべてで何かが欠ける。最も難しい組み合わせだが、
  唯一 `cipher_key` を取りながら系統が崩れる形なので「ハズレ」ではない。
- 秘密終幕は `desk` を選び、かつ三系統が揃ったときだけ開く。
  暗号の規則を自分で見つけた者だけが最後の一葉を読める、という筋にしてある。

## 6. 最終選択とエンディング

| 最終選択 | 場面ID | 条件 | 終幕 |
|---|---|---|---|
| ビードウズを名指し | `final_beddoes` | 三系統成立 | END 01 三十年目の潮 |
| ビードウズを名指し | `final_beddoes` | 系統不足 | END 02 灰色の朝 |
| 屋敷に出入りできた者を指す | `final_fordham` | 常に | END 04 白い手袋 |
| ハドスン生存説 | `final_runaway` | 常に | END 05 逃げた男 |
| 何も言わない | `final_silent` | 常に | END 03 テライ行きの船 |
| 手記の最後の一葉 | `secret_0` | 三系統＋`cipher_key` | END 06 火薬庫の返事 |

悪い結末の因果を、罰ではなく「何を見落とし、何を優先したか」に結びつけてある。

- END 02：正しい相手を指したが、相手の反論を封じる物がなかった。
  不足した系統に応じて、失敗理由の本文が差し替わる。
- END 03：真相よりも友人の家の名前を優先した。
- END 04：最も近くにいた者を疑った。医師には夜のアリバイがある。
- END 05：追う方角を間違え、真犯人に十一日を贈った。

## 7. 本文と状態の一致

`dynamicText` を使う場面では、持っている手掛かりだけを本文に出す。

- `c4_8`：足りない系統を名指しで挙げる
- `c5_0`：手の内の数を数える
- `final_beddoes_2`：三つの反論それぞれに、実際に持っている証拠だけを当てる
- `end_grey_0`：欠けた系統に対応する失敗理由だけを述べる

`tests/story-state.test.ts` が、未入手の証拠への言及と、
選んでいない同行者の行動を語っていないことを検査する。
