# AGENTS.md

## Project

This repository contains the Japanese browser mystery sound novel
**『グローリア・スコット号 ― 三十年目の潮』**.

It is an original adaptation of Arthur Conan Doyle's *The "Gloria Scott"* (1893),
which is in the public domain. All Japanese prose, branch structure, and endings
in this repository were written for this project. **Do not paste in text from any
existing translation** (Aozora Bunko or otherwise). If you need the source story,
work from the plot, not from someone else's wording.

Communicate with the user in Japanese unless the user requests another language.
Preserve Japanese punctuation, names, and typography — including full-width
spaces (U+3000), which are intentional and allowed by the ESLint config.

## Read first

Before changing story text, branches, UI, images, audio, or save behavior, read:

1. `docs/scenario.md` — chapter-by-chapter scene list
2. `docs/branching.md` — the 18-combination table and ending conditions
3. `docs/timeline.md` — who is where, holding what, at what hour
4. `docs/location-map.md` — physical geography of the manor, fen, and water channel

## Source of truth

- Branch conditions, evidence tracks, ending resolution: `content/branching.ts`
- Scenario prose and scene IDs: `content/story/*.ts`, assembled by `content/story.ts`
- Clue definitions: `content/clues.ts`
- Ending definitions: `content/endings.ts`
- Game state and transitions: `lib/game.ts`
- Audio synthesis and cue handling: `lib/audio.ts`
- UI and runtime behavior: `app/page.tsx`
- Responsive visual design: `app/globals.css`
- Scene art and character silhouettes: generated by `scripts/generate-art.mjs`

`content/branching.ts` is the only place branch decisions are made. **Do not
reimplement a branch condition inside `app/page.tsx`.** If the UI needs to know
something about the branch state, add a function to `content/branching.ts` and
call it.

`docs/branching.md` is documentation, not the source of truth. When the table and
the code disagree, fix whichever is wrong and update both — `tests/branching.test.ts`
holds an independent copy of the expected table specifically so that a change to
the implementation cannot silently change the spec.

## Critical scenario invariants

Do not change existing scene IDs, clue IDs, or ending IDs unless the user
explicitly approves a migration. IDs are the shared key for transitions, saves,
read-tracking, audio, backgrounds, and tests.

The evidence tracks are:

```ts
trackPast = ledger_name || news_clip || fordham_note;
trackAccess = sailors_knot || red_clay || hired_gig;
trackStaging =
  hudson_kit ||
  (tide_table && boat_log) ||
  trustVictor ||
  alone;
```

Required ending behavior:

- END 01 `tide`: accuse Beddoes with all three tracks.
- END 02 `grey`: accuse Beddoes with at least one missing track.
- END 03 `terai`: stay silent and suppress the memoir.
- END 04 `gloves`: accuse Fordham.
- END 05 `runaway`: claim Hudson fled alive.
- END 06 `powder`: all three tracks plus `cipher_key`, then read the memoir's last leaf.

There are 6 investigation pairs × 3 companion routes = 18 route combinations.
The expected result is **12 combinations with all three tracks and 6 with a
missing track**, and the secret choice is available in **5** combinations.

Each of the four investigation sites and each of the three companion routes must
contribute to at least one track or to the secret gate. `tests/branching.test.ts`
asserts this; do not add a site or route that changes nothing.

## Cipher invariants

Two ciphers appear in the story and **both must actually decode**:

- The gamekeeper's note (`c2_5`, `c4_0`): 24 words, read every third word from
  the 1st → 「猟期終了。ハドスン全部白状。至急逃亡手配」
- The memoir's last leaf (`secret_1`): 24 words, read every third word from the
  **2nd** → 「火薬三十樽、底に手当済。明後日決行。精算」

The offset difference is a plot point, not a mistake. `tests/story-state.test.ts`
verifies the word lists, the concatenated cover text, and the extracted words
against the prose. If you edit either letter, edit the test's word arrays to match
and confirm the decode still produces the stated plaintext.

## Story continuity rules

For every scenario edit, check:

- character location and travel route (Norfolk ↔ Hampshire is 150 miles);
- the ordering that makes the case work: Hudson leaves → Beddoes flees the *next
  morning*, **before** Hudson could have arrived;
- the tide window — the channel is passable only for about two hours around
  low water, which was 02:07 on the night Hudson disappeared;
- item ownership: the memoir, the note, Hudson's kit and money, the last leaf;
- whether the player actually obtained every item cited in an ending;
- whether a character is present and able to witness an event;
- whether the fen, the boat landing, the water channel, and the manor cellar
  remain distinct places.

Hudson was killed in the fen channel and weighted with garden railing. Beddoes
wrote the note as a warning, using a reading rule the two men agreed on in the
boat thirty years earlier. The explosion aboard the *Gloria Scott* was arson by
Hudson for an insurance payout, not a consequence of the mutiny — that is the
secret ending's revelation and must not leak into the common route.

## UX invariants

Preserve these behaviors unless explicitly asked to change them:

- The mobile UI shows one compact `操作` toggle while the tool menu is closed.
- Opening it reveals labeled controls: `音量`, `オート`, `スキップ`, `履歴`,
  `手掛かり`, `セーブ`, `操作`.
- Tool labels must remain legible on a phone and must not overlap the novel text.
- Space and Enter reveal the full text or advance when no choice is pending.
- Right Arrow advances when no choice is pending.
- Left Arrow opens earlier text as read-only history. It must not rewind state or
  allow a previous choice to be selected again.
- A choice must never be silently selected by Space or an arrow key.
- Manual save is available in the tool panel and via Ctrl+S/Cmd+S.
- After manual save, offer `ゲームを続ける` and `タイトルへ戻る`.
- Escape closes open menus and dialogs.

## Mobile and visual rules

- Test at narrow phone widths and with short viewport heights.
- Keep the text box, choices, characters, and tool menu from covering one another.
- Account for mobile browser chrome and safe areas (`100svh`, `env(safe-area-inset-*)`).
- Do not darken an image until its location becomes unreadable.
- `background-size: cover` crops artwork; each scene sets a deliberate focal
  position via the `.focus-*` classes in `app/globals.css`.
- Scene changes should be visually meaningful. The nine scene categories are not
  one background per literal location; when two scenes share a category, change
  weather, time, or framing so the player still perceives a move.
- Character silhouettes use transparent backgrounds and must match the people
  present in the scene.

Artwork is generated, not hand-committed:

```bash
npm run art
```

Edit the generator, not the SVGs. `tests/story-graph.test.ts` fails if a scene or
silhouette referenced by the story is missing, or if a declared silhouette is
never used. Both generators are deterministic, and CI fails if their output
differs from what is committed.

**Never paint an opaque layer over `.scene-layer`.** The title screen previously
composited `var(--paper)` on top of the background and hid the artwork entirely.
Overlays must be gradients with alpha below 1 at every stop, so the location
stays readable.

## Build and asset paths

The app is a fully client-side static site: `next.config.mjs` sets
`output: "export"` and `npm run build` writes `out/`. There is no `next start`;
use `npm run preview` to serve the export locally.

GitHub Pages serves the project at `/<repo>/`, so builds for Pages set
`NEXT_PUBLIC_BASE_PATH`. Next.js applies `basePath` to `<Link>` and `next/image`,
but **not** to a plain `<img src="...">` or a CSS `url()`. Scene backgrounds and
character silhouettes use both.

Every static asset URL must go through `lib/assets.ts`:

```ts
import { sceneImage, characterImage, asset } from "@/lib/assets";
```

A hard-coded `/scenes/...` or `/characters/...` string in `app/` is a bug — it
works locally and 404s in production. Verify asset changes with a basePath build:

```bash
NEXT_PUBLIC_BASE_PATH=/gloria-soundnovel npm run build
NEXT_PUBLIC_BASE_PATH=/gloria-soundnovel npm run preview   # http://localhost:3000/gloria-soundnovel/
```

Deployment runs only from `main` via `.github/workflows/pages.yml`. Do not deploy
or publish unless the user asks.

## Audio rules

There are no external audio assets. Everything is synthesized in `lib/audio.ts`
via the Web Audio API. Preserve these three cues:

1. `c3_8`: the *Gloria Scott* explosion — stop BGM, at least 2.5 seconds of
   complete silence, then the low blast.
2. `route_a_2` / `route_a_3`: the outbound and returning boat must be panned to
   opposite sides so the player can hear that it is the same boat twice.
3. `secret_3`: stop BGM before the silence while the second reading resolves.

`silence` means BGM and ambience actually stop, not merely a pause in the prose.
Do not add continuous music that masks evidence carried by sound. Every scene's
audible cues are also surfaced as a text caption (`audioCaption`) so the
information survives with the sound off.

## Save behavior

Saves use browser `localStorage` keys `gloria-save-v1` and `gloria-endings-v1`.

- Autosave happens on scene transition; manual save is separate.
- `SaveData` carries a `version` field. If the state shape changes, bump the
  version and add a migration, or intentionally change the key and report that old
  saves will not carry over.
- `loadSave` refuses a save whose scene ID no longer exists.
- Do not claim localStorage synchronizes across devices.

## Editing guidance

- Preserve unrelated user changes.
- Prefer focused patches over mechanical rewrites of the whole scenario.
- Keep story data, runtime logic, and presentation concerns separate.
- Do not deploy or publish unless the user asks for publication or deployment.

## Validation

```bash
npm run build
npm test
npm run lint
```

For branch changes, the 18-combination test must still enumerate and assert:

- track values;
- availability of the secret choice;
- Beddoes accusation destination;
- Fordham, Hudson-fled, and silence destinations;
- reachability of all six endings;
- that every investigation site and companion route still affects something.

For UI changes, manually verify at minimum:

- desktop landscape;
- narrow phone portrait;
- short-height phone viewport;
- tool menu closed and open;
- long prose;
- multiple-character scenes;
- choices, save dialog, help, clues, history, and ending list.

## Definition of done

A task is complete only when:

- the requested behavior is implemented rather than only documented;
- scenario and branch logic remain consistent;
- `npm run build`, `npm test`, and `npm run lint` all pass;
- mobile overlap and cropping are visually checked for UI or asset changes;
- any known limitation or unimplemented part is clearly reported.
